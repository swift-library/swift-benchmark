# Dimension Architecture

## Scope / Purpose

This document owns the numeric scale and DimensionCurve measurement
architecture.

`Benchmark.Scale` is the canonical numeric key for input-size curves.
`Benchmark.Dimension` remains a Benchmark-native compatibility metadata shape
for `.dimension(sizes:)`, but user-facing parameterization is now
Swift Testing-style `arguments`.

The implemented architecture only commits to a single Dimension. Multiple
dimensions, coordinate generators, rows-by-columns derived size, facets, and
heatmap analysis are future proposal scope.

## Current Implementation Status

Programmatic `Benchmark(... arguments:)`, Swift Testing bridge
`@Test(arguments:)`, and native `.dimension(sizes:)` compatibility paths
produce one measurement row per input. Numeric arguments infer
`Benchmark.Scale`; non-numeric arguments produce rows without curves. Report
preserves rows/samples, derives row metrics, and emits `Report.DimensionCurve`
records with amortized values for rows that have a scale.

## User Model

The primary user-facing spelling is `arguments`:

```swift
@Benchmark("Parse", arguments: [10, 100])
func parseDocument(_ size: Int) throws {
  try parser.parse(makeInput(size))
}
```

The generator runs once per size and produces the input used by measured
iterations for that size. Generator work is setup. It is not a measured
iteration and must not be included in samples.

Ordinary benchmarks have no Dimension:

```swift
@Benchmark
func parseSmallDocument() throws {
  try parser.parse(smallInput)
}
```

## Model

Target names:

- `Benchmark.ArgumentValue` / `Benchmark.ArgumentRow`: row metadata for
  parameterized benchmark declarations.
- `Benchmark.Scale`: Apple-aligned `Int` wrapper for numeric curve keys.
- `Benchmark.Dimension`: compatibility metadata for `.dimension(sizes:)`.
- `Benchmark.Dimension.Trait`: case-level trait metadata generated by
  `.dimension(sizes:)`.
- `Benchmark.Dimension.amortized(...)`: helper semantics for selected metric
  divided by `size.rawValue`.
- `Benchmark.Measurement`: the only benchmark measurement truth.
- `Benchmark.Measurement.Row`: one measured row with optional scale, arguments,
  and raw samples.
- `Report.Measurement`: Codable report projection of Benchmark measurement.
- `Report.Measurement.Row.metrics`: derived row metrics such as mean, median,
  p95, and p99.
- `Report.Measurement.Metric`: selector vocabulary for baseline, budget, diff,
  and curve generation.
- `Report.DimensionCurve`: derived structured curve record over measurement
  rows and a selected metric.

Avoid legacy input-size-derived and summary-derived names as durable architecture
names for the Dimension-first model.

## Measurement Truth

`Benchmark.Measurement` preserves rows and samples:

```swift
Benchmark.Measurement(
  rows: [
    .init(size: nil, samples: samples)
  ]
)
```

For a Dimension benchmark:

```swift
Benchmark.Measurement(
  rows: [
    .init(size: .init(10), samples: samplesFor10),
    .init(size: .init(100), samples: samplesFor100),
  ]
)
```

Raw samples remain the measurement truth. Report may materialize metrics and
curves for convenience, but those values are projections over measurement rows
and must be recomputable from samples.

## Execution Flow

```text
@Benchmark(.dimension(sizes:))
  -> Benchmark.Dimension.Trait
  -> _BenchmarkDiscovery
  -> BenchmarkDiscovery
  -> BenchmarkRunner.Plan dimension expansion
  -> BenchmarkRunner
  -> Benchmark.Measurement rows
  -> Benchmark.Event.Stream
  -> Report.Measurement
  -> Report.DimensionCurve
```

Benchmark owns declaration, discovery, plan expansion, runner execution,
measurement rows, and event context. Report owns Codable projection, derived
metrics, baselines, budgets, diffs, curve records, and attachments.

## Apple Alignment

Apple `swift-collections-benchmark` remains the trusted source for the
lower-level input-size mental model, but the local architecture does not copy
Apple task topology.

| Apple concept | Local concept |
| --- | --- |
| `Size` | `Benchmark.Scale` |
| `Measurement(size: time:)` | `Report.DimensionCurve.Point` derived from a measurement row |
| per-size task result | `Benchmark.Measurement.Row(size:samples:)` |
| amortized over size | `Report` field named `amortized`, selected metric divided by `size.rawValue` |
| charts/curves | structured `Report.DimensionCurve` records, not built-in presentation rendering |

Do not copy:

- monolithic benchmark app topology,
- `BenchmarkTask` as the core model,
- case-name suffixes as durable Dimension identity,
- a separate Dimension runner topology.

## Future Proposal Boundary

The current target is intentionally single-Dimension. The following are not
part of the implemented architecture:

- multiple Dimensions on one benchmark case,
- coordinate or Cartesian generators,
- rows-by-columns derived size,
- faceted comparison,
- heatmap analysis.

Those ideas are recorded in `../Decisions/FutureMultiDimensionMeasurement.md`
so they can evolve without contaminating the current model.

## Acceptance Evidence

- `.dimension(sizes:)` / `Benchmark.Dimension.Trait` macro and trait tests.
- Discovery tests preserving Dimension sizes and generator metadata.
- `BenchmarkRunner.Plan` Dimension expansion tests.
- Generator tests proving setup work is not counted as measured samples.
- Ordinary benchmark tests producing one row with `size == nil`.
- Dimension benchmark tests producing one row per size.
- `Benchmark.Event.Context` Dimension metadata tests.
- `Report.Measurement` JSON fixture tests.
- `Report.DimensionCurve` derivation tests.
- Amortized metric tests where `amortized == selected metric / size.rawValue`.
