# Benchmark Declarations

## Scope / Purpose

This document owns the benchmark declaration, trait, and discovery architecture.
It explains how users describe benchmark work and how tools discover that work
before execution.

The primary design rule is Swift Testing alignment:

```text
@Suite / @Test
  -> _TestDiscovery
  -> Test.all

@BenchmarkSuite / @Benchmark
  -> _BenchmarkDiscovery
  -> BenchmarkDiscovery
```

## Current Implementation Status

Current source implements the Swift-Testing-shaped declaration path:
`@BenchmarkSuite` / `@Benchmark` lower to `_BenchmarkDiscovery` sidecars and
`BenchmarkDiscovery` records, preserve source locations, carry suite/case
traits and tags, support parameterless and Dimension-parameter benchmark
methods, and feed `BenchmarkRunner.Plan` trait merge/scoping. See
`ImplementationScope.md` for the implemented capability matrix.

## Primary User Model

The primary user-facing authoring model is macro-first:

```swift
@BenchmarkSuite(.iterations(100), .baseline("parser-baseline.json"))
struct ParserBenchmarks {
  @Benchmark(.time(max: .milliseconds(30)), .dimension(sizes: [10, 100]) { size in makeInput(size) })
  func parseDocument(_ input: Document) throws {
    try parser.parse(input)
  }
}
```

Swift Testing projects use native suite/test traits:

```swift
@Suite(.benchmark(.iterations(100), .baseline("parser-baseline.json")))
struct ParserPerformanceTests {
  @Test(.benchmark(.time(max: .milliseconds(30))))
  func parseSmallDocument() throws {
    try parser.parse(input)
  }
}
```

`BenchmarkSuite` and `BenchmarkCase` are underlying internal/SPI or advanced
model targets for generated metadata, tools, fixtures, and adapters. They are
not public-first authoring contracts.

## Trait Model

Benchmark traits mirror Swift Testing's trait split:

- `BenchmarkTrait`: shared trait vocabulary where a trait can apply at more
  than one declaration level.
- `BenchmarkSuiteTrait`: suite-level defaults, budgets, baselines, diagnostics,
  scoping, and configuration.
- `BenchmarkCaseTrait`: case-level measurement, budgets, Dimension metadata,
  diagnostics, and overrides.
- `BenchmarkScoping`: suite/case scoping hooks when a trait needs setup or
  teardown behavior.

Suite-level traits are inherited or scoped into child benchmark cases during
`BenchmarkRunner.Plan` construction. Case-level traits can override, refine, or
add to suite-level traits according to each trait's merge policy.

## Dimension Traits

Dimension is declared through benchmark traits, not a parallel declaration
topology. It is a Benchmark core measurement concept.

`Benchmark.Dimension.Trait` is a `BenchmarkCaseTrait` generated by
`.dimension(sizes:)`.
It describes:

- one Apple-aligned input-size Dimension,
- `Benchmark.Scale` values,
- a generator that creates the input for each size,
- setup semantics that keep generation outside measured iterations,
- amortized metric semantics.

Discovery preserves `Benchmark.Dimension` metadata. `BenchmarkRunner.Plan`
expands each `Benchmark.Scale` into executable steps.
`Benchmark.Event.Context` carries Dimension context. `Benchmark.Measurement`
stores one row per size, and ordinary benchmarks use one row with
`size == nil`.

Report projects those rows into `Report.Measurement.Row.metrics` and
`Report.DimensionCurve`. Multi-Dimension and coordinate generators are future
proposal scope, not current declaration architecture.

The lower-level Dimension architecture is covered in `Dimension.md`.

## Discovery Model

Declaration macros lower to discoverable metadata:

```text
@BenchmarkSuite / @Benchmark
  -> generated benchmark records
  -> _BenchmarkDiscovery
  -> BenchmarkDiscovery
```

`_BenchmarkDiscovery` is internal/SPI. `BenchmarkDiscovery` is the materialized
tooling-facing discovery result. Package workflow and CLI commands consume
`BenchmarkDiscovery`; users do not maintain provider files.

Discovery rules:

- code declarations are the source of truth,
- no global mutable registration,
- no directory or target naming convention as the discovery contract,
- no public hand-written provider API,
- no `Provider` / `Probe` package workflow vocabulary,
- no Swift Testing `_TestDiscovery` internals copied into public contracts.

## Rejected Baggage

- Global `benchmark("Name") { ... }` as the product entry point.
- `BenchmarkTask` as the local core model.
- Instruments macros as benchmark declarations.
- Automatic insertion of `#span` / `@Instrumented` into benchmark bodies.
- Swift Testing runtime dependency in Benchmark core.

## Acceptance Evidence

- Macro expansion tests for `@BenchmarkSuite` and `@Benchmark`.
- Source-location tests at user declarations.
- Suite-level and case-level trait merge tests.
- `.dimension(sizes:)` / `Benchmark.Dimension.Trait` discovery tests.
- `_BenchmarkDiscovery` and `BenchmarkDiscovery` tests.
- Fixture package discovery without user-maintained providers.
